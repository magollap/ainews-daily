Claude Code · v2.1.329 · Nov 19, 18:49 UTC

Claude Code 2.1.329 shows where a folder's hooks come from before you trust it, and collects loops, schedules and forks under /tasks

This release focuses on supply-chain safety and visibility. The folder trust dialog now names the file that declares each hook, so a cloned repo can no longer quietly bring in hooks from a file you didn't expect. If hooks in managed settings fail to load, Claude Desktop and other non-interactive hosts now show a warning in the conversation instead of failing silently. /tasks now lists the session's scheduled tasks, /loop wakeups, the active goal and conversation forks, and you can stop any of them with x. /mcp gains a "Server message" row that shows the JSON-RPC error text when a remote HTTP MCP server refuses the connection. /status lists managed marketplaces that are excluded from auto-update and explains why.

Code Mode, which runs scripts that call tools, can now be turned on while OpenTelemetry events and metrics are enabled, and each tool call made from a script sends its own event. Tracing still turns it off. About 70 fixes follow. The ones that matter in production: ~/.claude.json could be reset to defaults after a network stall during a save; repeated macOS sign-outs happened when Keychain was readable but not writable; Code Mode could fill machine memory in a runaway loop and kept every large file it read in memory; MCP servers that send PDFs or Office files as application/octet-stream had them saved as .bin; and /code-review <pr> could review the checked-out branch instead of the pull request. It now reads the PR with gh pr diff. Self-hosted runners also get fixes for Git LFS, SSH host aliases and remote MCP reconnection.

＋ PositiveThe trust warning that names each hook's source closes a real repo-poisoning gap, and showing the MCP server's error text saves a lot of guesswork when an integration fails.
− NegativeThis is the second release in under a day with dozens of Code Mode fixes, including a memory runaway and a config file reset. Teams that pin versions should let a release settle before rolling it out widely.
Why it matters for builders
  1. Check repos with agent hooks before you trust them. The new dialog shows exactly which file adds each hook.
  2. If your telephony or agent stack uses OTel, you can now turn on Code Mode without losing per-tool telemetry.
  3. The MCP error-text row speeds up debugging of auth and protocol-version mismatches on remote tool servers.
  4. The octet-stream fix means PDFs and images returned by MCP tools are now readable by the model, which matters for document-heavy agents.
  5. Pin to 2.1.329 or later on shared machines to avoid the ~/.claude.json reset and Keychain sign-out bugs.

Agent security · Documentation analysis · Nov 19, 17:13 UTC

Codex's and Claude Code's network allowlists cover shell commands, not the MCP servers those agents launch

A six-document review of OpenAI's and Anthropic's official configuration docs separates three layers that are often treated as one: permission to reach the network, enforcing allowed destinations, and which processes the boundary covers. In Codex, command networking is off by default. Turning on network_access without also turning on features.network_proxy.enabled gives sandboxed commands unrestricted outbound access, so domain lists do nothing on their own. Admins can make the list exclusive with managed_allowed_domains_only=true. In Claude Code, the shell sandbox (Seatbelt on macOS, bubblewrap plus socat on Linux) is off by default. allowedDomains isn't a hard limit unless sandbox.network.strictAllowlist=true is set, which requires v2.1.219 or later. If sandbox startup fails, commands run unsandboxed unless managed settings set failIfUnavailable.

The key finding is that neither product's command allowlist covers MCP servers launched separately. Codex leaves MCP connections out of its proxy, and Claude Code runs local MCP servers outside the shell sandbox. Approving a server only decides whether it may run, not where it may send data. The authors note this is a reading of the documentation, not a penetration test.

＋ PositiveBoth vendors document strict, admin-only egress controls. With the right settings, sandboxed shell work can be locked down tightly.
− NegativeThe defaults are permissive, and MCP servers are a blind spot. An approved but compromised tool server can send data anywhere, whatever the command allowlist says.
Why it matters for builders
  1. Put MCP servers in their own container or network namespace with egress rules. Don't rely on the agent's allowlist.
  2. In Codex configs, turning on network access also requires turning on the proxy. One without the other leaves egress wide open.
  3. In Claude Code, set strictAllowlist, failIfUnavailable and allowUnsandboxedCommands=false through managed settings.
  4. Voice agents that call CRM or telephony tools through MCP carry customer PII, so egress control on those servers is a compliance issue.
  5. Keep a list of every tool server your agents launch. Approving a server only lets it run; it doesn't control where it sends data.

2 · New AI ToolsAgent tool governance

LangChain · LangSmith · Public beta · Nov 19

LangSmith Tool Gateway separates which tools an agent can use from whose credentials it uses them with

LangChain released the LangSmith Tool Gateway in public beta. Instead of giving every agent every tool and one shared service account, admins build curated tool kits for each role, for example a store-assistant kit and an inventory-agent kit. The gateway decides separately whose credentials a call runs under: the end user's delegated identity or a service identity. It connects to a range of MCP servers, loads only the tools relevant to a task so the model's context isn't flooded with tool definitions, and can require human approval for sensitive actions before a call goes through. Audit logs across the organization are limited to the Enterprise plan.

It addresses a common problem as agent fleets grow: tool sprawl, overly broad credentials, and no single place to answer which agent did what, on whose behalf. It takes on the same territory as cloud API gateways and identity vendors' new "agent identity" products.

＋ PositiveOne control point for scoping tools, choosing credentials and adding approvals is what security teams have been asking for before they'll approve production agents.
− NegativeIt's a beta, and the audit trail, which compliance teams care about most, is Enterprise-only. It also adds a hop, and some latency, to every tool call.
Why it matters for builders
  1. Per-role tool kits cut tool-definition tokens and lower the chance of the model picking the wrong tool, both of which affect latency in voice turns.
  2. Running tools under the user's own credentials makes "acting on behalf of" clear, which helps with banking- and health-style compliance.
  3. Approval gates fit voice well: the agent can say "I'll confirm that refund with a supervisor" instead of acting on its own.
  4. Measure the gateway hop. On realtime voice paths, a 50–100 ms overhead per tool call is noticeable.
  5. Even if you don't use LangSmith, copy the pattern: scoped kits, a credential broker and an audit log.

6 · DevOps & KubernetesAutoscaling · Networking · Edge

Karpenter · v1.15 · AWS Containers blog · Nov 19, 23:07 UTC

Karpenter 1.15 accounts for GPU and EFA topology before launching nodes, and stops node repair from breaking PDBs

Hardware-aware provisioning. Karpenter now uses Dynamic Resource Allocation for NVIDIA GPUs and EFA (through DRANET) when it sizes new nodes. It can require that a GPU and an EFA adapter share a PCIe root complex, which lets data move peer-to-peer without passing through the CPU and speeds up AllReduce in distributed training. The same path supports GPU time-slicing, so one physical GPU can be counted as several virtual devices. DRA needs EKS 1.34+, and time-slicing needs EKS 1.36+. Turn it on with the DRANVIDIAGPU and DRAEFA gates or Helm's settings.enableDRA. Karpenter also now checks EBS volume-attach limits before launch (for example, 25 on an m5.xlarge), which ends the launch-fail-relaunch loop for PVC-heavy pods. A new spec.enclaveOptions field brings Nitro Enclaves into dynamic scaling.

Safer repair. Node repair is now a voluntary disruption. It respects NodePool budgets and PodDisruptionBudgets, has a termination grace period per condition, and can be skipped with karpenter.sh/do-not-repair. A new RebootNode action clears GPU XID errors that the EKS Node Monitoring Agent marks as reboot-clearable without giving up a capacity-reservation slot. Terminate-first gates handle full NodePools and reservations. A PodDeletionCostManagement controller sets pod-deletion-cost so that scale-in empties the nodes Karpenter wants to consolidate, and NodeClassCEL computes maxPods and reserved resources per instance type from one EC2NodeClass.

＋ PositiveTopology-aware GPU placement and reboot-instead-of-replace directly cut wasted GPU hours and keep scarce capacity reservations.
− NegativeMost of the useful features are alpha feature gates, there are breaking metric-label changes, and the newest DRA paths need very recent EKS versions.
Why it matters for builders
  1. Self-hosted ASR, TTS or LLM inference on GPUs gets cheaper with time-sliced GPUs that Karpenter can now account for.
  2. Rebooting on transient XID errors means shorter outages for realtime voice pods than a full node replacement.
  3. Repair now respects PDBs, so live-call pods aren't evicted mid-conversation by an aggressive repair.
  4. CEL-computed kubelet settings make it easier to run mixed fleets of CPU gateway pods and GPU inference pods.
  5. Before upgrading, check dashboards that use the reason and consolidation_type labels.

7 · Voice AI CornerFull-duplex API · Voice cloning · Arabic speech

OpenAI API · gpt-live-1.1 · Nov 19–20

GPT-Live-1.1 arrives in the API, and a new Standby mode cuts the cost of idle voice time by 60%

The full-duplex model that has powered ChatGPT Plus and Pro voice since October 15 is now available to developers as gpt-live-1.1. It listens while it speaks, so barge-in is handled by the model. OpenAI says it handles accents more naturally and consistently across languages, captures exact letters and numbers more reliably (confirmation codes, emails, account IDs), follows instructions better, and completes tasks more often. It can hand complex workflows to a backend model of your choice mid-conversation without breaking the flow. It accepts and produces audio and text, streams over WebRTC or WebSocket, and supports function calling. It does not support image input, structured outputs or fine-tuning.

The new Standby setting works with both GPT-Live-1 and 1.1. You set an idle timeout of 5–60 seconds. After that much silence the model pauses, the WebRTC call stays open, and it resumes when someone speaks. Standby time costs $0.02/min versus $0.05/min active, and backend model and tool usage is billed separately. Developers spotted new voice IDs in the API (38 in total, including calandria, destello, halo and pearl). They also noticed that the 1.1 model page doesn't yet list per-tier rate limits. The Live API sits on its own sessions endpoint, so Realtime API integrations need adapting.

＋ PositiveModel-native barge-in, better accuracy on alphanumerics and a cheap idle state fix three of the biggest problems in production voice agents: interruptions, IDs and cost while on hold.
− NegativePer-minute pricing plus separately billed backend calls makes total cost harder to predict. Rate limits aren't published yet, and moving from Realtime isn't a drop-in change.
Why it matters for builders
  1. Calls with long silences (holds, lookups, IVR waits) can cost about 60% less in idle time. Tune the timeout carefully.
  2. Better letter and number capture means fewer "can you repeat that" loops when reading back confirmation codes and emails.
  3. Use the delegation pattern: keep the fast duplex model talking and send tool-heavy reasoning to a backend model.
  4. Budget per call minute, not per token, and track backend model spend per call separately.
  5. Load-test before switching. Rate limits are unpublished, and endpoint and session semantics differ from v1/realtime.

Each cloned voice is locked to the account and region that created it, the source audio is discarded after creation, and the voice takes on the single delivery style of its recordings. Seven languages are supported at launch. Customers must hold the rights and consent, and AWS recommends a documented consent and audio-approval workflow.

Google · Genie 4 · Gemini API + AI Studio · Nov 19

Genie 4 reaches the Gemini API: 720p, 24 fps interactive worlds with native audio, for about $0.10 per second

A day after it reached AI Ultra subscribers, Google made models/genie-4 available to paid-tier developers through the Interactions API (v1beta) and AI Studio. Google calls it its first world model built for developers. From a text prompt, a reference image or both, it generates a continuous 720p world at 24 fps with synchronized audio (ambient sound, effects, dialogue). Users move with WASD or arrow keys and can type prompts mid-session to change weather, lighting, objects or events, while Gemini reasoning keeps the world consistent. Key presses take effect in about 0.5 s, and text prompts in 1–2 s.

It streams over WebRTC for browsers or WebSockets for servers, and short-lived single-session tokens keep the main API key off the client. Pricing is $1.50 per million input tokens, $9 per million text output tokens and $17.50 per million video output tokens, about $0.10 per second (roughly $6 a minute) including stereo audio. Sessions are capped at 120 seconds. It is served from the US, Western Europe and Japan, and every frame carries a SynthID watermark. Reactor is an early partner using it for infinite interactive worlds. Google is also sending Project Genie waitlist invites to AI Pro users.

＋ PositiveA real-time, controllable, sound-on world model behind a standard streaming API opens up prototyping for games, spatial design and agent-training environments.
− NegativeAbout $6 a minute and a 2-minute cap limit it to demos and short experiences for now. Latency of 0.5–2 s is too slow for twitch-style interaction.
Why it matters for builders
  1. The WebRTC plus ephemeral-token pattern matches realtime voice stacks, so voice-driven world control is a natural combination.
  2. Use it to make synthetic environments for testing embodied or computer-use agents.
  3. Budget carefully: a 2-minute session costs about $12 at list price.
  4. SynthID on every output simplifies provenance and labeling compliance for generated media.
  5. Prototype interactive demos and onboarding; keep production game loops on traditional engines for now.
