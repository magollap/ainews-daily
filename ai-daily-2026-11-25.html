Top Story · OpenAI · Research · Nov 24

OpenAI says it has settled matrix multiplication: the exponent ω is exactly 9/4, with a matching lower bound

OpenAI added a preprint to its public openai/math repository, dated November 24 and titled "The matrix multiplication exponent is nine fourths". It claims to have pinned down ω exactly. ω is the number that measures how fast two n×n matrices can be multiplied as n grows. The October preprint showed only an upper bound, ω ≤ 9/4, over the complex numbers. The new paper claims the upper bound holds over every field and adds a matching lower bound: any formal arithmetic circuit for n×n multiplication needs at least ⌈n9/4/2⌉ nonscalar multiplications or divisions for every n ≥ 2. It also argues that the geometric border rank of the matrix-multiplication tensor is at least n9/4 and that its asymptotic rank equals n9/4. A companion paper on Euclidean geometry in the asymptotic spectrum of tensors supplies the framework for the lower bound.

The claim is a big one. Strassen's 1969 algorithm brought the exponent down to about 2.807, and decades of human work had only reached about 2.371. Most theorists expected the true answer to be ω = 2. A proven 2.25 would overturn that expectation and close one of the central open questions in algorithms. The caveats are also big. The paper isn't peer-reviewed. It is credited only to "OpenAI", with no named authors and no statement of which model, if any, found the proof. The Lean formalization covers only division-free circuits, while the stated bound also counts division gates, so the machine-checked part and the headline claim don't fully line up; one digest estimates about 42% of the results are formalized. The result has no practical effect on GPUs: it doesn't give a usable algorithm at real matrix sizes, and production kernels will keep using classical or Strassen-style methods. Coverage started overnight (Interesting Engineering, 03:52 UTC), it reached 716 points on Hacker News, and it lands in a week of AI-assisted math claims that includes the Claude-aided Riemann proof and Anthropic's VP≠VNP repository.

Anthropic · MCP · Claude & Claude Code · Nov 24

MCP servers can now ship Skills to Claude, and long-running Tasks and mid-call Elicitation are generally available

Anthropic changed three things about how Claude works with MCP servers. The biggest is Skills over MCP, now in public beta. A server can publish skills alongside its tools. A skill is a directory with a SKILL.md file and optional supporting files, delivered through MCP's existing Resources primitive. That lets a server ship expertise — best practices, step-by-step workflows, playbooks specific to an account or organization — instead of only a list of tool names and descriptions. Claude loads a skill only when it is relevant, which keeps context use low, and skills update when the server does, so users install nothing separately. In Claude Code (v2.1.332) they appear in the / menu as server:skill. Launch partners are Shopify (storefront design end to end), HubSpot (customer onboarding inside Claude), Atlassian (organization context for work analysis) and Carta (drafting and issuing equity from an uploaded document, coming soon). Skills are on by default for Pro, Max and Ultra, available on Team once an admin enables them, and "coming soon" for Enterprise.

Tasks are now generally available. Previously a tool call had to finish before Claude could carry on. Now a server can run a long operation, or an entire agent loop, in the background while Claude keeps working, and collect the result later; ZoomInfo uses it for account research that used to need several prompts. Elicitation is also GA. It lets a server pause in the middle of a tool call to ask the user for input through a form or a link, then resume. Supabase confirms costs before creating a paid project and before destructive SQL, Railway asks before removing a service, and GitHub makes the user type the repository name before an agent deletes it. File Uploads are rolling out soon: Claude will hand PDFs, spreadsheets and images straight to MCP servers without routing them through the context window. Anthropic says the MCP SDKs now see more than 700M downloads a month and Claude has over 10,000 connectors. The "85% less context" figure some outlets attached to Skills in fact describes tool search.

Anthropic · Claude Desktop · Artifacts · Nov 24

Claude artifacts can be installed as Mac and Windows apps, with a top tier that can run any program on your computer

A new beta lets an artifact be installed as a desktop app with its own icon and window, opening from Finder or the Start menu and able to interact with the operating system. You install one through Share → Install as app or the artifact's right-click menu, and an artifact can include its own install button. There is no packaging, code signing, API key or separate login: the app runs on your Claude account, so you must be online and signed in to open it. It needs Claude for Mac or Windows 6.28899.0 or later and is rolling out in beta from Free through Enterprise. On Team the top permission tier stays off until an admin enables it; on Enterprise the whole feature is off until an owner turns it on in Organization settings → Artifacts.

There are three permission levels. Default allows only what the artifact could already do in a browser. App permissions add notifications, global keyboard shortcuts, floating above other windows (which also exposes cursor position across screens) and a macOS menu-bar or Windows tray icon. Full access to this computer lets the app run any program and read, change or delete files without asking each time. Permissions are granted per app version, so every update — including your own edits — asks again, and a refusal sticks. Full access can be granted only to apps you made, or on Team and Enterprise to apps made inside your organization. Anthropic states plainly that it does not review apps before installation, and warns that code an app loads from another site can change without a new prompt. Revoking access can reload or close the app and stops programs it started. There is no Linux, web or mobile support; template artifacts, legacy artifacts and Cowork live artifacts can't be installed; HIPAA-ready organizations are excluded; and in organizations with zero data retention for Claude Code, installed apps are not covered by that policy. Anthropic's own demos include a layered image editor (Linnet), a file manager (Phosphor), a rules-based organizer (Sift), a terminal (Tern) and a tray performance monitor (Vitals).

＋ The upsideThis is the shortest path yet from a prompt to a native internal tool. Anyone can build a dashboard, tray monitor or file utility with no installer, certificate or app-store review.
− The downsideThese are unreviewed, model-generated programs, and one tier can delete files and launch anything. Re-asking after every edit will be noisy, and zero data retention does not extend to installed apps, which matters in regulated environments.
Why it matters for builders
  1. Internal tools such as call-QA dashboards or live agent monitors can become one-prompt desktop apps for your operations team.
  2. Keep anything that touches credentials at the Default or App tier. Full access belongs to throwaway local utilities.
  3. Admins should check the Team default (on) and set a full-access policy before staff start installing.
  4. A tray app showing live concurrency and call metrics is a quick win for a voice-agent team.
  5. Claude is becoming an application platform, so plan for distribution through Claude, not only the browser.

Launch HN · Versine (YC F26) · Agent payments · Nov 24

Versine puts money movement behind an MCP, with a passkey signature on every payment the agent proposes

Versine launched on Hacker News (90 points, 79 comments) as a Venmo-like service your AI can drive. It splits bills or trips, pays or requests money from up to 100 people at once, pays people who aren't users at all (they cash out to a bank in about two minutes), and pays "trusted contacts" without asking every time. Underneath, the MCP sits in front of a self-custodial USDC wallet on Base, with keys held through passkeys; Plaid handles bank linking, and Bridge and Coinflow handle conversion between dollars and stablecoins. It ships as iOS and Android apps, as an MCP inside ChatGPT and Claude, and as a public MCP plus REST API.

The approval design is the interesting part, because it keeps the agent out of the trust path. The agent makes an MCP call to start a payment. A push notification arrives in the mobile app. The user swipes up and approves with a passkey or biometrics. The app then builds the exact transaction shown on screen and the passkey signs it directly, so neither the agent nor Versine's server can alter the amount or recipient. That signature creates a one-time permission for the wallet to send that amount to that address. For recipients who aren't users, the signature authorizes a fixed amount to a future address created after the recipient verifies a one-time code, and the claim link expires in seven days. Trusted contacts have a cap per seven days, enforced on-chain per recipient with overall limits on Versine's server. The company says it isn't a licensed money transmitter because it never holds user funds; the plan is an "agent-first bank" earning from deposit interest and cards.

＋ The upsideSigning the exact on-screen transaction with a passkey is the right answer to "what if the agent pays the wrong person". On-chain per-recipient caps mean the limit is enforced by the wallet, not by a server you have to trust.
− The downsidePayments are final: no chargebacks and no disputes if an agent pays the wrong person. A compromised trusted contact can drain up to the cap, a lost passkey or hijacked iCloud account puts funds at risk, and KYC makes this US-only in practice. Venmo or Cash App could copy it in a quarter.
Why it matters for builders
  1. Copy the pattern, not necessarily the product: sign the exact action the human saw, not a token the agent can reuse.
  2. Per-recipient on-chain caps are a cleaner spending guardrail than prompt instructions, which agents can be talked out of.
  3. If your voice agent will ever take payment, decide now whether you need reversibility. Stablecoin rails don't offer it.
  4. "Trusted contacts" is a useful abstraction for recurring payees where re-approval every time kills the experience.
  5. Watch the money-transmitter claim. Regulators may not agree that self-custody exempts the service.
Epochal · Forecasting · Developer platform · Nov 24

Epochal's Time Portal rebuilds the web as it was on any past date, so forecasting agents can be tested without hindsight

Three founding members of xAI — Guodong Zhang, Zihang Dai and Manuel Kroiss — launched Epochal with $100M, which Bloomberg's source says is largely Zhang's own money. The product, Time Portal, is a point-in-time web: an archive of more than 1T pages and over 7T URLs spanning 30+ years, with minute-level versions for fast-changing pages. (One outlet reports 10B pages, so treat the corpus figures as the company's own.) It has three parts. Search returns only pages that existed at the chosen moment. Fetch returns the newest capture at or before that moment and returns a miss rather than substituting a later snapshot. Sandbox is a Linux environment frozen to that moment — system clock, Ubuntu version, libraries, runtimes, package mirrors and network all respect the cutoff — whose filesystem is discarded when it stops. It also marks pages that later disappeared as absent, removes duplicates, and adjusts ranking as the meaning of search terms shifts over time. Access is through an Accept-Datetime header, with Python and Rust SDKs, a CLI, an MCP server and a free console playground.

The validation claim is the sales pitch: on 347 live forecasting questions, errors replayed inside Time Portal correlated 0.98 with the original live errors, while replays on the live web after the answer was known correlated only 0.16, and replays with no web access 0.49. In other words the environment reproduces the difficulty of not knowing, which is exactly what leaks when you backtest an agent on today's internet.

Nvidia · Open weights · Image generation · Nov 25

Nvidia quietly posts Nemotron-Labs-Image-30B-A3B, an autoregressive image model that writes pictures as tokens

Nvidia published weights for Nemotron-Labs-Image-30B-A3B, an image generator that works like a language model rather than a diffusion model. The prompt enters a NemotronHForCausalLM backbone initialized from Nemotron 3 Nano, which interleaves Mamba-2 state-space layers with attention layers in a 30B-total, 3B-active mixture of experts, trained with progressive mid-training followed by GRPO reinforcement learning. The backbone then emits discrete visual tokens from a vocabulary of the 131,072 text tokens plus a fixed codebook of 196,560 Leech-lattice vectors, and a separate ~642M-parameter tokenizer decodes those tokens into pixels. It renders at any multiple of 16, such as 1024×1024 or 1248×832, and acts as the raster engine inside Nvidia's "Pixel as Code" VisualCreation framework; the companion VisionCode models are held back pending legal clearance.

The vendor-reported numbers are mixed rather than dominant. It leads on GenEval (92.86 against 89.00 for GPT Image 2), LongTextBench (97.98), CVTG-2K (92.53), WISE Verified (91.50 against 87.60 for Nano Banana Pro) and BizGenEval (86.0). It loses clearly on GenEval2 (65.43 against 81.00) and on Qwen-Image-Bench (52.46 against 65.23). Note the date caveat: coverage appeared Nov 25 at 09:36 UTC, but the companion paper showed as two days old on Hugging Face, so the upload itself may predate our window.

＋ The upsideOne architecture for text and images means a single serving stack, and a state-space backbone is cheaper at long sequence lengths than attention alone. Open weights let researchers study autoregressive image generation at 30B scale.
− The downsideThe NVIDIA licence restricts it to non-commercial research and evaluation, so it isn't really open. It needs 4× H100 80GB, CUDA 13 and trust_remote_code, with no Diffusers pipeline — and it loses to GPT Image 2 on two benchmarks.
Why it matters for builders
  1. You cannot ship this commercially. Read the licence before planning anything around it.
  2. If autoregressive image generation keeps closing the gap, your text and image serving converge onto one runtime.
  3. Four H100s for inference puts self-hosting out of reach for most teams; the hosted APIs stay cheaper.
  4. GenEval2 is the harder instruction-following benchmark. Weight it above GenEval when comparing image models.
  5. Mamba-attention hybrids are becoming normal. Expect them in multimodal voice stacks next.

It is a mixture of experts with 480B total parameters and about 28B active — up from 114B total and 6B active in the Preview — pre-trained on about 4T tokens from roughly 1B samples, about three times the Preview's data. It generates 4 to 30 seconds in a single take at native 1080p and 25 fps across six aspect ratios, with synchronized audio covering lip-synced dialogue, sound effects, ambience and music. The architecture is worth understanding because it explains the audio sync. A single-stream Transformer puts text, video and audio tokens in one sequence, so motion, lip shapes and sound are generated together rather than stitched afterwards. A Multi-Head Latent MoE splits each token into independent heads, each with its own router and expert pool. To make that affordable across nodes, "Head Parallel" first exchanges activation slices between nodes in a fixed pattern determined by which node owns which head, then keeps the data-dependent top-k expert routing local to each node — the fixed communication happens before the unpredictable routing, not around it. Custom infrastructure (MagiFSDP, MagiMoE kernels, the MagiMuon optimizer) handles scale, and Sand.ai reports about 22% faster training than LatentMoE at matched FLOPs. Finally a latent spatiotemporal upscaler lifts the base output and re-injects the original reference images during upscaling. On Artificial Analysis Video Arena v2.1 its four-task average Elo is 1150.3, up 151.8 from the Preview's 998.5. Why it matters for builders
  1. Single-pass audio and video means you can generate a spoken scene without a separate TTS and lip-sync stage.
  2. At $0.08/second, a 30-second product video costs $2.40 — cheap enough for per-customer personalization.
  3. The single-stream design is the direction of travel: joint audio-video models will reach realtime avatars next.
  4. Don't architect around the promised open weights until they exist. Preview is all you can self-host today.
  5. Verify the parameter count and benchmark claims yourself; the launch partners already disagree with each other.
