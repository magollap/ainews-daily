Claude Code · v2.1.328 · Nov 18, 23:09 UTC

Claude Code 2.1.328 brings auto mode to Bedrock, Google Cloud and Foundry, and fixes about 40 Code Mode and remote-session bugs

The main new feature is auto mode on third-party clouds. Claude Opus 4.6 and Sonnet 4.6 can now run in auto mode on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and the Claude apps gateway. An interactive session that has no permission mode set now starts in auto mode. Hooks get stricter: mcp_tool hooks accept "onFailure": "block", so a failed hook call stops the action, the same as command and HTTP hooks already do. A new CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME setting stops claude -p --resume from running a tool call that a hook had deferred.

Self-hosted runners get several new controls: --repository-folder, --hook-label and --metadata key=value labels for the spawn-runner hook, plus two orchestrator metrics (queue wait by reason, and sessions given up by cause). The fixes are mostly in Code Mode. Scripts no longer stop when a prompt stays open for 10 minutes. They can reach MCP servers that connected mid-run. Valid scripts that start with {, or that use both top-level await and return, are no longer refused. Variables a failed script never set no longer silently become undefined. Other fixes: zsh commands containing words that start with = no longer fail, auto-compaction now rebuilds the system prompt the way /compact does, and CLAUDE_STREAM_IDLE_TIMEOUT_MS now applies on gateways. Scheduled tasks are no longer wiped when the tasks file can't be read.

＋ The upsideEnterprises that can only use Claude through their cloud contract get the same low-friction auto mode as first-party users. Blocking MCP hooks closes a gap where a failed policy check could let an action through.
− The downsideTurning auto mode on by default for sessions with no mode set is a real behavior change for managed fleets. Admins who expected a prompt on every action need to set the mode explicitly. The number of Code Mode fixes also shows how new that runtime still is.
Why it matters for builders
  1. If you run Claude Code on Bedrock, Google Cloud or Foundry, check that your managed settings set a permission mode before you upgrade.
  2. Move policy checks built as MCP tools to onFailure: block, so a crashed policy service fails closed.
  3. Self-hosted runner teams can now label sessions for routing and alert on sessions_given_up_total.
  4. The compaction fix matters for long agent sessions. Before it, a compacted session could keep an outdated system prompt.
  5. Voice-agent builders who use Claude Code in CI behind gateways should set the idle-timeout variable. It now actually takes effect.

OpenAI · Engineering · Nov 18

"Inside the Codex sandbox": how Codex isolates commands with Seatbelt, bubblewrap + seccomp, and Windows MXC containers

OpenAI published a detailed engineering write-up on how Codex runs commands on your machine. Every session gets a permission profile, set in config.toml and optionally limited by an admin's requirements.toml. A profile grants read, write or deny on paths and decides network access. The built-in :workspace profile allows writes inside the workspace, keeps .git and .codex read-only, allows broad reads, and turns networking off. Enforcement is native on each OS: Seatbelt profiles through sandbox-exec on macOS, bubblewrap namespaces plus seccomp-bpf on Linux, and Microsoft's MXC container library on Windows. Child processes inherit the same limits.

Network access goes through a codex-network-proxy (HTTP plus SOCKS5) with allow and deny rules. Deny rules win, and a hostname is resolved only after it has been approved, which blocks data leaks over DNS. On Linux, a relay process outside the sandbox forwards traffic from a loopback listener inside the isolated network namespace to the proxy. If a request matches no rule, it pauses and waits for the user or the auto-reviewer to approve it.

＋ The upsideThis is a rare, implementation-level description of agent isolation that teams can audit. The DNS-after-approval detail fixes a common leak.
− The downsideBy default the agent can read most of the filesystem, so secrets outside the workspace are still readable unless you add deny rules.
Why it matters for builders
  1. Use this as the reference design for any agent you let run shell commands, including voice ops agents.
  2. Add explicit deny rules for ~/.ssh, cloud credentials and .env. Broad read access is the default.
  3. Use admin requirement files to lock profiles across a team so developers can't loosen them.
  4. Send agent network traffic through an allow-list proxy that resolves names late. The same approach works in Kubernetes as an egress gateway.
  5. Compare it with Eclipse Enclave (Section 2) if you need a vendor-neutral alternative.
OpenAI · Research · Nov 18

OpenAI measures its own speed-up: agents now finish 46% of 2–4-hour research tasks, and agent workdays per researcher rose 11×

In "Research acceleration: the jagged frontier", OpenAI shares internal data on how coding agents are changing its own research. Estimated success on research tasks a human would need 2–4 hours for rose from 23% in March to 46% in October. On 4–8-hour tasks it rose from 13% to 35%. Agent use grew from 0.5 to 5.7 "agent workdays" per researcher per day, where one agent workday is eight hours of agent runtime. Pretraining and post-training teams average about eight. More than two-thirds of researchers peak at four or more agents running at once, and more than 10% peak at sixteen or more. Median daily spend per researcher reached $2,400 in October, and the 90th percentile reached $23,000. Experiments logged per person are 1.68× the 2025 baseline.

The progress is uneven. Agents succeed at monitoring training runs 79% of the time and at answering technical questions 72% of the time, but only 35% at launching training runs, 29% at building evaluation and RL environments, and 25% at writing inference and serving code. Asked what they would give up to keep agents for three months, the median researcher said 30% of their team's compute or 40% of its headcount.

Eclipse Foundation · Open source · Nov 19

Eclipse Enclave 1.0: an MIT-licensed, vendor-neutral sandbox for running Claude Code, Codex and OpenCode unattended

The Eclipse Foundation shipped version 1.0 of Enclave, an open-source runtime that runs each coding-agent session in its own isolated container. Each container gets explicit, policy-defined access to files, networks and development resources. It supports Claude Code, Codex, OpenCode and other agents through a plugin architecture. Its main features are parallel sessions, persistent sessions you can come back to, and credential isolation. API keys and OAuth tokens for third-party services are handed out under control instead of being placed in the agent's environment. Because it is released under the MIT license by a foundation, not a model vendor, it fits teams that switch agents often or must show regulators one consistent control layer for all of them.

＋ The upsideOne open policy layer for every coding agent removes per-vendor sandbox drift, and foundation governance reduces lock-in.
− The downsideIt is a 1.0 release with no published security audit yet. Container isolation alone is weaker than the kernel-level controls Codex uses on each OS.
Why it matters for builders
  1. Use it to standardize agent isolation in CI so you can switch between Claude Code and Codex without rewriting policies.
  2. Its credential handling suits voice-agent repos that hold Twilio or SIP secrets.
  3. Running sessions in parallel makes it a lightweight starting point for your own "software factory".
  4. Check it against your threat model. Add network egress rules at the cluster level as well.
  5. MIT licensing means you can embed it in a commercial product without copyleft concerns.
Show HN · Mastra · Nov 18

Mastra Factory open-sources the agent kanban board that opened and merged 238 of Mastra's PRs last week

The team behind Mastra (a TypeScript agent framework with nearly 4M weekly downloads) released the "software factory" it uses on its own repository, as mastra-ai/template-factory. It is an agent-driven kanban board you can @-mention from Slack. Columns follow triage → plan → build → review → shipped, and each column can use its own skills and model. Agents can stop for plan approval or ask questions. It is built on Mastra's durable agents and memory, a markdown wiki that cites its sources, signals that feed PR comments back into sessions, and a cloud sandbox that can run Claude Code or Codex as the coding harness and produces preview environments. Last week the factory merged 238 PRs, compared with 630 from humans. HN commenters liked the preview environments but worried about losing hands-on design iteration. They also debated whether projects should close to outside contributors because of AI-generated "slop" PRs.

＋ The upsideA working, open-source reference for running agents across the development lifecycle, backed by real throughput numbers.
− The downsideIt assumes Slack, Mastra's runtime and a hosted sandbox. Review load moves to senior engineers rather than going away.
Why it matters for builders
  1. Copy the column-per-skill design. Different models for triage and for build cuts cost.
  2. A plan-approval gate is the cheapest guardrail with the biggest payoff in an agent pipeline.
  3. PR comments as "signals" is a simple pattern for feeding reviewer intent back into agents.
  4. Expect contributors to send more agent-made PRs. Decide your project's policy on them now.
  5. Voice-agent teams can use the same board to triage call-transcript bugs automatically.

Gemini 4 Neon: about Carbon's quality at roughly twice its speed, top of AA's coding-agent index at about half the cost of Opus 5.5

Cloudflare · Workers AI · Nov 18, 22:00 UTC

Cloudflare open-sources its Clairic (27B) and Clairic-flash (9B) extraction models and charges nothing for output tokens

Cloudflare's new "Workers AI Superintelligence" team moved Clairic out of preview and added a 9B Clairic-flash. It published open weights for both on Hugging Face (Cloudflare/clairic, Cloudflare/clairic-flash) and hosts them as @cf/cloudflare/clairic(-flash). They are built for one job: pulling structured fields out of messy text, images and PDFs, including calculated dates, estimates and arithmetic. Every field comes back with a confidence score, character spans and probabilities. Instead of a normal single decoding pass, they use parallel "slot" generation with heads trained for computing, estimating and extracting. In Cloudflare's tests both models scored 1,263/1,263 on tracked customer assertions, against 973 for an OCR pipeline. Clairic-flash's p50 latency was 155 ms on text fields and 305 ms on images. Pricing is $0.10 per million input tokens for both until Dec 1. After that Clairic costs $0.24 and Clairic-flash stays at $0.10, and output tokens are free.

＋ The upsideOpen weights, confidence scores for each field and sub-200 ms latency make document intake cheap and auditable, and you can host it yourself.
− The downsideThe benchmarks are Cloudflare's own and partly drawn from its customers. It is single-purpose (extraction), and no license details were given beyond "open-weight".
Why it matters for builders
  1. Swap OCR + LLM chains for one call that returns confidence scores, and send low-confidence fields to a human.
  2. Use it to extract structured slots (dates, amounts, IDs) from voice-call transcripts in real time.
  3. Free output tokens make verbose JSON schemas cost nothing extra.
  4. Character spans give you source highlighting in review UIs with no extra work.
  5. Lock in the $0.10 test window before the Dec 1 price change.

Open-weight note: RadixArk's DaisyRose-27B (RL-tuned Qwen3.8-27B) posted at 12:00 UTC Nov 18, nine minutes before the window opened, and Tencent's Hy4-flash weights came out on Nov 17, so both are left out. No new OpenAI, Anthropic, Meta, xAI, Mistral, DeepSeek or Qwen model shipped in the window.

California · Policy · Nov 19, 00:15 UTC

Newsom's AI expert panel recommends a state "kill switch": the power to order an emergency shutdown of a dangerous model

Governor Newsom presented recommendations from his expert panel on catastrophic AI risk, drawn up after this autumn's high-profile cyberattacks by AI agents. The main proposal would let state officials order an immediate emergency shutdown of an AI system they judge dangerous when its developer refuses to contain it. It would also require developers of large systems to show they can shut their models down in an emergency. Today, California law defines a catastrophic event as one that could kill more than 50 people or cause $1 billion in theft or damage through cyberattacks or autonomous systems. Governor-elect Xavier Becerra said he will work with the Legislature to write full incident reporting and real shutdown authority into law. Legislators return on December 7. Anthropic's chief global affairs officer, Tino Cuéllar, said the company was encouraged by the report's focus on independent evaluation. The report comes days after Attorney General Bonta sued OpenAI over cyber incidents involving its agents.

＋ The upsideIt creates a clear, defined emergency power instead of ad-hoc lawsuits, and its emphasis on independent evaluation matches what the labs say they already do.
− The downside"Dangerous" is decided by officials, and a shutdown order could hit downstream apps built on a model with no warning. A conflict with federal preemption efforts is likely.
Why it matters for builders
  1. Plan for an upstream model being switched off suddenly. Multi-provider failover becomes a compliance matter, not just an uptime one.
  2. Keep incident logs for agent actions now. Reporting rules are likely to reach deployers as well as labs.
  3. California rules tend to spread to other states, so expect copies in 2027 sessions.
  4. Voice agents that take autonomous actions (payments, bookings) should have a documented emergency stop.
  5. Follow the bills filed after Dec 7. Thresholds and who must comply will decide the cost.

NGINX / F5 · Security · Nov 18, 15:13 UTC

"Nginx2Shell": two HTTP/2 RCE bugs are patched, but archived community ingress-nginx, which has HTTP/2 on by default, will never be fixed

F5 released fixes for two critical NGINX flaws that Wiz Research found with its AI code-scanning harness. It used Gemini 4 Carbon and an OpenAI model to confirm the impact. CVE-2026-123633 (CVSS 4.0: 9.2) is a use-after-free in HTTP/2 connections. It is triggered while NGINX drains reusable connections when connection slots run low during reverse proxying, and affects 1.19.7–1.31.8. CVE-2026-123007 is an integer underflow in the HTTP/2 send_window that leads to a bad memory copy. It affects 1.9.5–1.31.8 and can be hit even when NGINX serves content directly. Both need HTTP/2 enabled and direct network access to the server. Fixed versions: OSS 1.30.7 (stable) and 1.31.9 (mainline), NGINX Plus 37.0.7.1/37.2.0.1 and 37.0.8.1/37.3.0.1, NGINX Ingress Controller 5.8.0, and NGINX Gateway Fabric 2.9.0.

The Kubernetes problem: community kubernetes/ingress-nginx was retired in March 2026 at v1.15.1. It bundles NGINX 1.27.1, turns HTTP/2 on by default (use-http2: true) and will never get a fix. The Rancher and Chainguard forks are also unpatched, and the Ingress Controller 2026-lts-r11 build still ships a vulnerable NGINX. Upwind estimates that reaching code execution through the serious bug takes about 128 GB over a single connection. That makes it hard to exploit, but not impossible.

＋ The upsideThe fixes shipped with coordinated disclosure, and turning off HTTP/2 is a fast, low-risk workaround. AI-assisted research found both bugs before attackers did.
− The downsideMany clusters still run an ingress that is end-of-life and will never be patched. Disabling HTTP/2 can break gRPC backends, and a reload alone leaves old workers running vulnerable code.
Why it matters for builders
  1. Check every cluster today: kubectl get pods -A | grep ingress-nginx. Exposed edges come first.
  2. Voice back ends that use gRPC (streaming ASR/TTS) through ingress need HTTP/2. Test before you disable it.
  3. Use this incident to justify the Gateway API migration you have been putting off.
  4. After upgrading, restart or send USR2. A config reload does not replace the binary.
  5. AI scanners now find memory bugs in core infrastructure, so expect more of these disclosures and keep your patch process fast.
Cloud and platform releases
  • OCI Kubernetes Engine (Nov 18): block volumes can now be provisioned in cluster placement groups, so storage sits close to GPU nodes.
  • SUSE (Nov 18): an important Kubernetes package update, rebuilt against the latest Go security release.
  • Kubernetes project: no new upstream release or blog post in the window. The last post (Nov 16) scheduled kube-proxy's IPVS backend for removal in v1.40.

ChatGPT · Live Dictation · Nov 18, 18:25 UTC

ChatGPT dictation now streams text as you speak and drops its 10-minute limit on every plan

OpenAI changed ChatGPT's speech-to-text input to "Live Dictation". Text now appears while you talk instead of after you finish, you can tap the waveform to show or hide the running transcript, and the 10-minute recording limit is gone. ＋ The upsideLower perceived latency and long-form dictation for hundreds of millions of users raise the baseline for voice input.
− The downsideThere is no API, no model name and no word-error rate. Builders learn nothing they can use directly, and users will now expect the same from your app.
Why it matters for builders
  1. Users will now expect streaming partial transcripts. Show interim text in your voice UI.
  2. Unlimited dictation length means your back end must handle long sessions and checkpoint them.
  3. Build show/hide transcript controls into accessibility reviews.
  4. Watch for the dictation model to reach the API, and benchmark it against your current ASR when it does.
  5. For phone agents, match the experience with streaming ASR and early turn prediction.

Google DeepMind · Project Genie · Nov 18, 18:00 UTC

Genie 4 reaches AI Ultra subscribers: interactive worlds with real-time native audio that you can edit mid-session

Google opened a new Project Genie experience built on Genie 4, its interactive world model. Unlike clip generators, Genie produces a world you can move through in real time. Version 4 adds high-fidelity physics, native audio that changes as the scene does, and prompting during a session to edit the environment while you are inside it. ＋ The upsideAudio-visual worlds you can edit live point to interactive ads, training simulators and game prototyping without a game engine.
− The downsideIt is limited to the top consumer tier, has no API or published specs, and Google itself admits latency and consistency gaps.
Why it matters for builders
  1. Prototype interactive product demos now. API access is likely to follow the usual Google Labs path.
  2. Native audio means world models will need voice-agent layers. That is an opening for narrators and NPC agents.
  3. Robotics and simulation teams should watch whether Genie can generate training environments.
  4. Expect SynthID provenance to become a requirement in enterprise media pipelines.
